Section 1: .NET Core & C# (10+ Questions)


Q1: What are the key differences between .NET 6, 7, and 8, and what improvements does each bring?
Answer: 
.NET 6 introduced unified SDK, LTS, minimal APIs, top-level statements. .NET 7 added rate limiting middleware, output caching, HTTP/3 support, improved regex source generators. .NET 8 (LTS) brought Blazor unified model, native AOT for web APIs, keyed DI services, frozen collections, improvements in System.Text.Json, and significant performance gains (SIMD, vectorized operations).
•	.NET 6: Unified, LTS, Hot Reload, Minimal APIs
•	.NET 7: Performance leader, Rate Limiting, HTTP/3, Native AOT preview
•	.NET 8: Native AOT GA, Keyed DI, Frozen Collections, Blazor Unified, Primary Constructors

Q2: Explain Minimal APIs in ASP.NET Core and when to prefer them over controllers.
Answer: 
Minimal APIs reduce ceremony for lightweight HTTP endpoints. Defined directly in Program.cs using app.MapGet/MapPost etc. Best for microservices, simple REST APIs, and performance-critical scenarios. Pros: less boilerplate, faster startup, better for AOT. Cons: no built-in filter pipeline comparable to MVC, harder to structure for large apps. Controllers remain preferable for complex apps needing attribute routing, model binding, global filters, and clear separation of concerns.

Q3: How does async/await work under the hood in C#? What is the state machine generated by the compiler?
Answer: 
The C# compiler transforms async methods into a state machine class implementing IAsyncStateMachine. Each await point becomes a state. When execution reaches an await, if the awaitable is not complete, the method registers a continuation and returns to the caller. When the task completes, the continuation resumes from the last saved state. Key points:
•	SynchronizationContext is captured by default (use ConfigureAwait(false) in library code)
•	async void should be avoided except for event handlers
•	ValueTask<T> reduces heap allocations for hot paths

Q4: What is the Task Parallel Library (TPL)? How does Parallel.ForEach differ from async/await?
Answer: 
TPL provides abstractions for parallelism and concurrency. Parallel.ForEach uses multiple threads for CPU-bound work, dividing data partitions across thread pool threads. async/await is for I/O-bound work, freeing threads while waiting. Use Parallel.ForEach for CPU-heavy loops (image processing, computation). Use async/await for DB calls, HTTP calls. Channels (System.Threading.Channels) provide high-performance producer-consumer pipelines.

Q5: What are Background Services (IHostedService) and how do you implement a Hosted Worker?
Answer: 
IHostedService provides StartAsync and StopAsync hooks managed by the .NET generic host. BackgroundService is an abstract base with ExecuteAsync. Use cases: background job processing, scheduled tasks, message consumers. Register with builder.Services.AddHostedService<MyWorker>(). Best practices: respect CancellationToken, handle exceptions, use Polly for retries, and leverage channels for work queuing.

Q6: What is Entity Framework Core and explain lazy loading vs eager loading vs explicit loading.
Answer: 
EF Core is an ORM mapping .NET objects to database tables. Three loading strategies:
•	Eager Loading: Include() fetches related data in one query. Good for known relationships.
•	Lazy Loading: Requires proxies (UseLazyLoadingProxies). Automatically loads related data on property access. Risk: N+1 problem.
•	Explicit Loading: context.Entry(entity).Collection().LoadAsync(). Load on demand without proxies.
Best practice for performance: use eager loading for known access patterns, projection (Select) to DTOs for read-only queries.

Q7: Explain the difference between IEnumerable, IQueryable, and IAsyncEnumerable.
Answer: 
IEnumerable: in-memory iteration, executes in .NET process. IQueryable: builds expression tree, translates to SQL/remote query. IAsyncEnumerable (C# 8+): async streaming of data, useful for large result sets from DB or HTTP streams. Misusing IEnumerable where IQueryable is needed causes full table loads into memory.

Q8: What are Records in C# and when should you use them over classes?
Answer: 
Records (C# 9+) are reference types with value-based equality semantics. Value records (record struct in C# 10) are value types. Use records for:
•	Immutable DTOs/command/query objects
•	Pattern matching scenarios
•	Data transfer where equality by value is needed
They auto-generate Equals, GetHashCode, ToString, and support with-expressions for non-destructive mutation.

Q9: What is the Span<T> and Memory<T> and why are they important for performance?
Answer: 
Span<T> is a stack-only struct providing a contiguous view over memory (array, stack, native). Memory<T> is the heap-compatible version. They enable zero-allocation slicing and parsing. Key in high-performance scenarios:
•	Parsing HTTP headers without allocations
•	Slicing arrays without creating subarrays
•	Working with stackalloc
Combined with System.IO.Pipelines, they underpin ASP.NET Core's request processing performance.
